Governance exists to keep the documentation trustworthy, not to add ceremony.
The smallest useful process is the one that proves the claim, records the
tradeoff, protects restricted information, and leaves the next engineer a safe
operating path.

Start with the product and operational doctrine when a change affects user
intent, identity, money, location, safety, country activation, provider
availability, or public feature wording. Use an ADR when the change also makes
a durable architectural tradeoff.

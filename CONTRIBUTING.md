# Contributing to the Architecture Documentation

Contributions must remain public-safe and implementation-aligned.

1. Confirm the statement against source code, a canonical MySQL script, or an
   approved operational policy.
2. Label optional or future behavior as configurable or planned.
3. Do not include credentials, account IDs, resource names, internal addresses,
   customer data, screenshots of consoles, or detailed defensive thresholds.
4. Update navigation links when adding or moving a chapter.
5. Run the repository link and secret checks before opening a pull request.

Architectural changes should include context, decision, alternatives,
consequences, rollback considerations, and affected runbooks.

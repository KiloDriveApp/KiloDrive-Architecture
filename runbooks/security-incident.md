# Runbook: Security Incident Response

## Stages

1. **Triage:** validate signal, assign severity/owner, protect reporter and user
   data, establish a restricted evidence record.
2. **Contain:** revoke affected sessions/keys, isolate a node/provider/country
   capability, and stop unsafe money or document operations.
3. **Preserve:** retain relevant audit, cloud, database, deployment, and provider
   evidence with chain-of-custody controls.
4. **Eradicate:** patch root cause, rotate secrets, remove persistence, and test
   authorization and data integrity.
5. **Recover:** restore service gradually with heightened monitoring and
   reconciliation.
6. **Notify:** follow contractual, store, regulator, law-enforcement, and user
   notification duties based on verified impact.
7. **Learn:** document timeline, control gaps, corrective actions, owners, and
   exercise/test updates.

Never coordinate a live incident in a public GitHub issue. Public disclosure is
reviewed, accurate, and does not expose users or defensive details.
